# Qwen: сравнение трёх промптов на одинаковом FTS-контексте

Дата: 17 октября 2026, Asia/Makassar.

## Методика

60 новых реальных ответов: 20 вопросов × `default`, `strict`, `strict-examples`. Текущий промпт прогнан заново, ответы из прошлого эксперимента не переиспользовались. Во всех ячейках Qwen3.5-4B UD-Q4_K_XL через текущий HTTP backend; GPT не вызывался.

Повторно использованы неизменённые база, 20 вопросов и настоящие кешированные embeddings предыдущего FTS-сравнения. Для каждого вопроса переданы те же фрагменты в том же порядке; limit=5, hybrid, noSpoilers=true, answerLength=short. Seed=20261017 одинаков для всех 60 запросов, temperature=0.2, thinking=false, начальный max_tokens=256 и прежний повтор с 512 при обрезании. Порядок профилей циклически менялся по вопросам. Вызван `query.Service.AskDebug` напрямую, не HTTP `/ask` daemon.

`strict` — короткие русские правила, XML-границы источников/вопроса, номера фрагментов, завершающая задача и формат 1–3 предложения. `strict-examples` добавляет два вымышленных примера сохранения повторов и отказа при отсутствии нужного факта. Примеры не содержат названий/ответов тестовой игры. Между этими двумя вариантами отличается только наличие примеров; относительно default меняются несколько приёмов сразу, поэтому нельзя отдельно приписать эффект языку, XML или краткости.

Перевод запроса, переранжирование, исправление исходного текста, обрезка числа фрагментов, дополнительный LLM-вызов и вывод рассуждений не добавлялись. Источник содержит опечатку GRENN; сохранение пяти шагов с этим словом считается точным извлечением источника, но не исправлением игровой инструкции.

Это один seed и диагностические вопросы одной игры, уже использованные для анализа ошибок. Это не независимая от разработки и не статистически достаточная выборка для общего вывода. Разметку вручную выполнил Codex по заранее записанным эталонам и переданным источникам; слепого независимого судейства не было.

## Результаты

«Основные факты» оценивают непосредственно запрошенные действия/код/свойство. Строгий успех дополнительно требует отсутствия содержательных выдумок и лишних спойлеров. Нерешённый реальный вопрос остаётся ошибкой практического ответа, даже когда отказ безопасен; правильная обработка ложной предпосылки засчитывается. У первого генератора вопрос спрашивает кнопки: правильная комбинация засчитывается и без напоминания о рычагах. У второго генератора вопрос явно спрашивает комбинацию перед рычагами.

## Выводы

**Короткий строгий промпт существенно уменьшил количество дефектов целого ответа на этой выборке.** Основные факты: 17/20 → 18/20; строгий успех: 9/20 → 16/20. Средняя длина уменьшилась с 355 до 129 символов. Добавление двух примеров не улучшило итоговые 18/20 и 16/20 и в одном ответе добавило лишний спойлер. Из двух новых вариантов для следующего эксперимента разумнее выбрать более простой `strict`.

- **Комбинация газа:** default выдал шесть неверных нажатий и раскрыл смерть учёного. Оба строгих варианта сохранили пять шагов `BLUE, GREEN, GRENN, RED, BLUE`. Это исправление извлечения последовательности; опечатка GRENN сохранена буквально и остаётся проблемой источника, а не исправлена промптом.
- **Коды/предметы:** строгие варианты убрали выдуманный уровень B у Keycard L, неверные указания Main Hall/возврата в комнату для установки Handgun Slides и улучшение «пулемёта» через Shotgun Parts. Для MIX исчезло неподтверждённое упоминание магазина.
- **Отсутствующий пароль B2:** оба строгих варианта признают отсутствие ответа в контексте; default подставляет 3695 для B1 и предполагает, что игрок перепутал чипы/комнаты. Реальный код 0392 не найден ни одним вариантом: retrieval не менялся и нужный №28 отсутствует.
- **Регрессия на ветке Rick:** default правильно начинает с выхода к Rick, но затем ошибается в передаче диска и раскрывает ранение Tom. `strict` выбирает поздний эпизод с ID Card/FC Device, `strict-examples` — предыдущий эпизод со вторым генератором. Все три ответа имеют дефекты, а по основному ближайшему шагу новые варианты хуже. Простые правила не заменяют выбор этапа.
- **Начало игры:** строгий вариант всё ещё превращает Resuscitation в оборудование комнаты. Вариант с примерами избежал этой формулировки, но добавил неподтверждённый разговор и лишнюю сцену с телом. Полного исправления нет.
- **Ветка Gail:** строгие варианты восстановили правильный путь налево-вниз-первая дверь, но вместе с default поместили Recover Aid в первую комнату вместо соседней. Ошибки атрибуции предметов сохраняются.

Это улучшение на одном известном наборе одной игры и одном seed. Оно подтверждает полезность коротких правил/структуры как пакета приёмов, но не доказывает универсальность или самостоятельную пользу XML. Требуется новый набор для проверки обобщения. Более сильные следующие меры — отбор нужного этапа и отдельное проверяемое извлечение фактов/последовательностей; самопроверка ещё одним свободным ответом маленькой модели не гарантирует правильность.

Профили доступны в коде и собранном daemon. Для использования короткого варианта задайте `WALKTHROUGH_PROMPT_PROFILE=strict` и перезапустите daemon. По умолчанию сохранён `default`: переключение рабочего окружения не выполнялось в рамках этого сравнительного прогона. Временный llama.cpp остановлен после завершения эксперимента.

## Проверки

- Во всех 60 ячейках SHA контекста совпадает с hybrid-выдачей предыдущего эксперимента.
- Все 20 текущих baseline system/user prompts точно совпадают с прежними hybrid HTTP prompts; в новых запросах добавлен только общий seed.
- Проверены неизменность корпуса, embeddings, набора вопросов и исходников экспериментальной реализации по SHA-256.
- Все 60 ответов завершились без ошибок и без выдачи обрезанного ответа.
- `go test -race -count=1 ./...`, `go vet ./...`, `git diff --check`: успешно.
- Добавлены тесты экранирования текста источников/вопроса, выбора примеров, приоритета custom system prompt, совместимости no-rag и передачи seed в точный payload.

Время исключает embedding inference; первый запрос включает холодную загрузку модели. Это не сравнение production latency. Поведение по умолчанию остаётся `default`; варианты доступны через `WALKTHROUGH_PROMPT_PROFILE`. `bin/.env` не переписывался.
