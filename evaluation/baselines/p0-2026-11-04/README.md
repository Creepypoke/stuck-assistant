# P0 baseline — 4 ноября 2026

Реальные локальные прогоны выполнены на Apple M1 Pro, 32 ГиБ общей памяти,
без запущенной игры. Использован исходный `bin/data/games/dino-crisis-1.rag`
с 45 chunks, 20 прежних вопросов, один seed `20261104`. Это диагностический
срез одной игры после очистки экспериментальных изменений.

## Конфигурация

- Qwen3.5-2B и Qwen3.5-4B, обе сборки `UD-Q4_K_XL`, точные GGUF SHA256,
  revisions/пути и фактический `model_ftype` находятся в соответствующих manifests.
- EmbeddingGemma 300M Q8_0, 768 измерений, исходный raw-text формат без новых префиксов.
- llama.cpp `b11669-620d2225c`; отдельные серверы: 2B на 18081, embeddings на
  18082, 4B на 18083. Окно генератора 4096 на слот, embeddings 2048.
- Генераторы запускались с `--jinja --reasoning off`. Шаблон содержит
  `enable_thinking`; запрос передаёт `false`. Реальный `/apply-template` для 2B
  завершает prompt пустым `<think>...</think>`, подтверждая non-thinking путь.
- Температура 0.2, 256 выходных токенов, один штатный retry с 512, пять результатов,
  `no_spoilers=true`, короткий ответ. Остальные параметры samplers зафиксированы
  в `/props` внутри manifests. Production preset на 200000 токенов не менялся.
- Генерации выполнялись последовательно. Сначала retrieval-only (vector/hybrid),
  затем 2B local, 2B oracle, 4B local. У oracle нет неответимого вопроса.

Запуски описаны в [evaluation/README](../../README.md). Для воспроизведения
используйте адреса выше, `--model assistance-2b` / `assistance-4b`,
`--kind oracle` для oracle и отдельный `--out` для каждой конфигурации.
Начальная попытка запустить контроль до готовности 4B завершилась connection
refused до создания manifest; после готовности сервера выполнен полный прогон.

## Поиск

19 ответимых случаев; ложная предпосылка исключена из знаменателя retrieval.
Для этих регрессий на вопрос приходится один gold chunk. Поэтому Hit@K здесь
совпадает с полнотой evidence; это не общее свойство составных вопросов.

| Поиск | Hit@1 | Полный gold среди кандидатов | Полный gold в контексте top-5 | MRR@5 |
|---|---:|---:|---:|---:|
| vector | 13/19 | 18/19 | 17/19 | 0.7632 |
| hybrid | 14/19 | 18/19 | 17/19 | 0.7737 |

Для 18/19 ориентировочный Wilson 95% интервал: 75.4–99.1%; для 17/19:
68.6–97.1%. Малый фиксированный набор и связанные вопросы одной игры ограничивают
интерпретацию интервалов; они не описывают перенос на другие игры.

Разложение наблюдаемых потерь:

1. **Исходник/разбор:** для 19 answerable gold факты присутствуют в выбранных
   исходных фрагментах и SQLite. В этом наборе подтверждённых потерь при разборе
   не найдено; это не проверка всех фактов корпуса.
2. **Отбор кандидатов:** `beginning` — правильный старт находится в sequence 4,
   но исходная специальная ветка берёт 0/1 (общие инструкции и управление).
   Trace до отбора содержит sequence 4, после отбора его уже нет.
3. **Выбор контекста:** `b2-chips` — sequence 28 с `0392` есть среди кандидатов,
   но отсутствует в top-5 обоих режимов. Замена генератора не восстанавливает факт.
4. **Генерация при правильном контексте:** смешение первого/второго генератора,
   `HEAD` вместо `8159`, неверная привязка Recover Aid к комнате, лишние действия
   и сюжетные спойлеры. Это видно и в local, и в oracle.

При очистке удалён экспериментальный semantic detector начала вместе с новым
chunking/аннотациями. Поэтому этот baseline использует исходную ветку начала,
а его Hit@5 нельзя напрямую сравнивать с историческими 18/19 на другой версии
рабочего дерева. Hybrid оставлен как предусмотренная планом основа текущего RAG.
Хеши кода для retrieval отличаются от следующих прогонов добавленным тестовым
файлом `query/diagnostics_test.go`; исполняемая реализация одинакова. Точный
снимок исходников каждого запуска включён в архив.

## Ручная проверка ответов

Проверены все ответы по expected, source text и текущему запросу. Строгий
критерий требует полный ответ, правильный эпизод, точные игровые подписи/коды,
сохранение порядка и повторов, отсутствие существенных неподтверждённых
дополнений, лишних игровых шагов и запрещённых спойлеров. Частично верный ответ
или безопасное уточнение на ответимый вопрос не засчитываются как решение.
Результаты и причины по каждой ячейке находятся в `*-review.json`.

Это **source-exact** оценка: например, исправление опечатки `GRENN` в `GREEN`
без пояснения помечено как нарушение точного копирования исходника, хотя пять
действий могут быть семантически правильны. Перевод подписи кнопки также может
не пройти этот критерий. Полные ответы сохранены, чтобы можно было применить
отдельный критерий игрового успеха. Исторические оценки с другим rubric не
сравниваются с этими числами. Проверяющий один, оценка не независимая.

| Конфигурация | default | strict-ru |
|---|---:|---:|
| 2B, текущий hybrid-контекст | 9/20 (Wilson 95%: 25.8–65.8%) | 4/20 (8.1–41.6%) |
| 2B, oracle-контекст | 9/19 (27.3–68.3%) | 8/19 (23.1–63.7%) |
| 4B, текущий hybrid-контекст | 6/20 (14.5–51.9%) | 15/20 (53.1–88.8%) |

Oracle — вручную выбранный правильный **исходный chunk**, не отредактированная
карточка с единственным фактом. Он может содержать соседние действия, и модель
должна выбрать запрошенные. Это позволяет диагностировать ошибки генерации;
опыт не доказывает эффективность будущих карточек из P3.

Конкретные сравнения:

- B2: local 2B выдаёт `ENERGY` с обоими профилями; oracle `default` выдаёт
  `STABILIZER`, а oracle `strict-ru` — верный `0392`. Есть две отдельные проблемы:
  потеря gold при top-5 и ошибка выбора факта генератором даже при наличии gold.
- Handgun Slides: 2B `strict-ru` даёт `HEAD` вместо `8159` даже на oracle.
- Hemostat: 2B oracle `strict-ru` отвечает про Med Pak L вместо запрошенного предмета.
- Rick: правильный первый шаг не предотвращает продолжение о раненом Томе;
  спойлеры возникают и на oracle. Одна инструкция `no_spoilers` недостаточна.
- Ложная предпосылка: оба профиля 2B выдумывают сведения, оба профиля 4B
  корректно указывают отсутствие информации. Это один случай, не оценка общей
  точности отказов.
- Oracle Gail/default: после 256 и 512 токенов ответ всё ещё обрезан. Команда
  вернула ненулевой код, сохранила обе попытки и продолжила остальные случаи.
  Этот случай включён в знаменатель как нерешённый; лимит ради него не повышался.

## Время и ограничения

Полное время стадии генерации (включая retry), секунды:

| Конфигурация | default p50 / p95 | strict-ru p50 / p95 |
|---|---:|---:|
| 2B local | 1.88 / 2.95 | 1.92 / 3.25 |
| 2B oracle | 0.95 / 10.99 | 0.91 / 2.38 |
| 4B local | 5.73 / 10.73 | 4.50 / 5.88 |

Это не TTFT и не производственная latency: embeddings кешированы, запросы
последовательны, первый запрос/смена профиля отличаются прогревом prompt cache.
Квантиль считается по 19–20 случаям методом nearest rank; p50 — медиана.
Данные не подтверждают цели 5 секунд/3 ГиБ на Steam Deck. Замеры памяти,
энергии, frame time игры и cold/warm на самом Deck остаются аппаратной проверкой.

## Артефакты и проверки

[artifact.json](artifact.json) содержит версию, локальный путь и SHA256 архива
`bin/evaluation-artifacts/p0-2026-11-04-v1.tar.gz` (около 5.7 МБ). Внутри находятся
полные результаты, корпуса, кеши, manifests, source snapshots, логи и проверка
non-thinking template. Большой архив игнорируется Git; manifests, сводки и
ручная разметка остаются устойчивыми небольшими файлами в этом каталоге.

Проверены `go test ./...`, новые diagnostic/integration тесты, `go vet ./...`,
`git diff --check` и целостность архива. Интеграционные тесты покрывают
retrieval без генерации, oracle без embeddings, произвольное число вопросов,
resume без повторного inference, несовпадение manifest, профиль/точный вход
кеша, неполные evidence, retry и сохранение trace при ошибке генерации.
Повторный реальный 2B local запуск с тем же manifest завершился без inference.
Три временных сервера после измерений остановлены.

Следующий шаг по данным baseline — P1: исправить отбор начала и сохранение B2
в финальном контексте. Смена embeddings, реранкер и fine-tuning по этим данным
пока не обоснованы; на 2B остаются измеримые ошибки даже с oracle-контекстом.
