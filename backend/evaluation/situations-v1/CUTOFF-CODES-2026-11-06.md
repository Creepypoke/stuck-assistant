# Отсечение слабых источников и коды из карточек — 6 ноября 2026

Прототип двух изменений на корпусе B (`build-recovered-v3/B`), 38 вопросов, Qwen 2B, seed 20261104, hybrid, cap 2400 токенов. Ручная проверка по rubric из `runs/B-local/review.json` **не выполнена**: ниже автоматические проверки кодов и последовательностей и выборочное чтение ответов.

## Что изменено

- `query.Config.RelativeScoreCutoff`: после retrieval остаются источники с cosine ≥ cutoff × лучший cosine; первый всегда остаётся. Сервис: `WALKTHROUGH_RELATIVE_SCORE_CUTOFF`, runner: `--relative-cutoff`. По умолчанию выключено.
- `query.Config.CodeAnswers`: если вопрос про код/пароль, у верхней карточки ровно один проверенный код, а у других оставшихся источников нет другого кода — ответ собирается без модели: код + цитата источника. Иначе отвечает модель. Сервис: `WALKTHROUGH_CODE_ANSWERS=1`, runner: `--code-answers`. По умолчанию выключено.
- Схема `situation-v1`: необязательное поле `exact_code` (список). Принимается, только если каждый код дословно есть в цитате source span. `data-preparation` записывает его из `Card.ExactCode`.
- Корпус `build-codes-v1/B` — копия B с добавленным `exact_code` для 17 карточек; тексты поиска и embeddings не менялись. Оригинал B не изменён (SHA256 `0b368d1f…`).

Cutoff 0.85 выбран по этому же набору (на прогоне B-local ни одно нужное доказательство не терялось даже при 0.95), то есть подобран на тестовых вопросах.

## Важное ограничение: промпт изменился во время эксперимента

Во время работы в рабочем дереве параллельно изменили промпт и убрали `answer_length: short` (`query/service.go`, `query/prompts.go`, `cli`, `service`, docs). Новый промпт просит развёрнутые ответы «куда идти, зачем, на что обратить внимание». Поэтому сравнение с ревью `runs/B-local` некорректно. Все три прогона ниже сделаны на одном и том же исходном коде query/prompt (совпадают `source_sha256` в manifests) и отличаются только двумя настройками.

## Наблюдения

- **Коды из карточек**: сработали на 8 вопросах, все 8 — верный код без лишних утверждений; цитата содержит и остальное, о чём спрашивали (Keycard L, предметы в сейфе, «choose Yes», «use it on the Handgun»). Минус: эта часть ответа — английская цитата, а не фраза на языке вопроса. Защита от неоднозначности сработала: на `ambiguous-computer`, `planning-disc-safe`, `b1-chip` и `b1-b2-distinction` ответ остался за моделью.
- **Cutoff исправляет путаницу эпизодов**: с 5 источниками модель дала код B1 вместо B2 (`b2-chips`) и последовательность первого генератора вместо второго (`second-generator`); с cutoff оба вопроса указывают на правильный эпизод (последовательность второго генератора всё ещё неполная).
- **Cutoff ухудшает**: `first-generator` дважды обрезан по `max_tokens` (ошибка); `planning-disc-safe` перечисляет все три кода третьей стратегии; при одном источнике модель чаще дословно копирует служебные метки (`Evidence: baseline-block-005:…`, `emergency-red`) и дописывает выдуманные детали («нажмите кнопку H»). Выдуманные детали есть и в базе — их провоцирует новый промпт.

## Вывод и следующие шаги

Коды из карточек выглядят как безопасный выигрыш: верные коды без выдуманных дополнений. Эффект cutoff смешанный, и без ручной проверки делать вывод рано. Дальше:

1. Дождаться окончательной версии промпта и провести ручную проверку всех трёх прогонов по прежней rubric.
2. Убирать метки `[evidence:…]` и `situation_id` из текста, который получает модель.
3. Отвечать на остальную часть вопроса (предмет, выбор Yes) фразой на языке вопроса, а не только цитатой.
4. Проверить cutoff на новых вопросах, а не только на тех, по которым его подбирали.
