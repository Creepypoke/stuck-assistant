Это не стоимость первоначальной разработки/разметки и не память процессов моделей. Время авторской семантической подготовки отдельно не измерено. В ранней сборке v2 хеширование целого GGUF повышало Python peak до 1.71 GB; в v3 оно заменено потоковым. Все максимальные embedding-входы ниже 2048 (control 299, A 379, B 293 токена). SQLite integrity_check, совпадение поисковых входов/хешей сохранённых векторов, FTS и отсутствие изменений при read-only проверке прошли.

Langfuse: [Backend evaluation](http://localhost:3000/project/walkthrough-backend). Загружены штатным `langfuse/pipeline.py` и затем прочитаны обратно **410 items, 2644 scores, 11 experiments**. Никакой независимый LLM judge не использовался. К прежним проверкам добавлен экспорт привязанных к ответам ручных `task_pass`, `episode_error`, `unsupported_addition`, `spoiler`, `exact_code`, `exact_sequence`. Source-exact оценка по-прежнему хранится в `gold_strict_pass`.

Проверки реализации: Go tests и vet для явного списка `./cli ./cmd/... ./embeddings/... ./evaluation/runner ./ingestion/... ./llama ./logging ./query ./service ./storage/...`; шесть Python-тестов exporter; `git diff --check`. Новые проверки покрывают несовпадение source span/версии, разные представления поиска/ответа, весь набор составных evidence, сохранение старых баз, целые evidence при token cap и привязку ручных scores к точному ответу. Имена моделей/токенизация/trace проверены реальными локальными запросами. Старые вопросы/gold не перезаписаны: новый набор находится рядом с экспериментом.

Далее имеет смысл развивать B: компактный доказательный контекст дал измеренный прирост фактических ответов и меньший контекст. Перед использованием в сервисе нужны исходный английский корпус, полноценная sentence/branch-safe сегментация всего прохождения, независимая проверка карточек и ответов, несколько seeds и слепые вопросы. Отдельные эксперименты нужны для отказов/уточнений (сейчас 0/4), выбора начального эпизода, исключения машинных branch labels из текста ответа и соблюдения ограничений выбора предметов. Изменение EmbeddingGemma prefixes, reranker, query rewriting и детерминированный вывод кодов не оценены; их эффект этим прогоном не доказан. Для полной проверки оригинального baseline нужен явно разрешённый доступ к соответствующему `.rag` в `backend/tmp/` либо его копия по другому пути.
