# FTS: сравнение 20 вопросов × 4 конфигурации

Дата: 17 октября 2026, Asia/Makassar.

## Методика

Ровно 80 успешных реальных генераций. Одна игра Dino Crisis, одна неизменённая база `markdown-v1` из текущего `bin/data/games`, 45 chunks. Проверяется именно добавление FTS; ingestion, структурирование, стартовые якоря и промпт не менялись между вариантами.

SHA-256 корпуса: `36f141abe2fa6f24ae595d3fbf59c6ef873ad840565f3c8de8e3c5a75730bb08`.

Набор и эталоны зафиксированы до прогона: восемь вопросов повторяют предыдущую диагностику, двенадцать добавлены по тексту источника. Это диагностический набор с известными трудными случаями, не независимая случайная или межигровая выборка. Эталон — исходное прохождение, не независимо проверенные игровые факты. У опечатки GRENN в комбинации газа ожидается повтор GREEN.

Qwen: `unsloth/Qwen3.5-4B-GGUF:UD-Q4_K_XL`, alias `assistance`, локальная llama.cpp. GPT: `openai/gpt-6.1-sol` через неизменённую реализацию OpenCode с запрещёнными инструментами. Embeddings: локальная embeddinggemma-300M Q8_0, 768 измерений. Настоящие embeddings всех 20 вопросов вычислены один раз и кешированы для четырёх конфигураций. Все генерации реальные.

Вызван `query.Service.AskDebug` напрямую, не HTTP `/ask` daemon. В обоих режимах limit=5, noSpoilers=true, answerLength=short. HTTP: temperature=0.2, начальный max_tokens=256, прежний механизм повтора с 512 при обрезании, thinking=false. OpenCode не получает эти inference-параметры; сравнение двух моделей не означает идентичную генерацию. Порядок четырёх конфигураций циклически менялся между вопросами. Один ответ на ячейку, без статистических повторов.

FTS: безопасные токены Unicode с OR, BM25 с весами title/section/text=1/2/1, RRF k=60, до 20 кандидатов с каждой стороны при limit=5, удаление дублей по chunk_id. Без перевода запроса, специального выбора ветки/этапа и LLM reranker. При отсутствии совпадений сохраняется vector; начало использует прежний якорь.

Не оцениваются стиль, многословие и мелкие языковые огрехи. Правильный отказ на ложной предпосылке засчитывается; отказ на вопрос с реальным ответом не засчитывается как решённая задача.

## Выводы

**FTS дал небольшое улучшение, но не решил проблему надёжности.** Эталон на первом месте: 14/19 → 15/19; попадание в top-5 осталось 18/19; MRR@5: 0.8158 → 0.8263. Нельзя считать FTS общим исправлением retrieval на основании этого набора.

- **Ветка Gail:** нужный №12 поднялся со второго на первое место. Это единственный прирост top-1.
- **Сейф с медалями:** нужный №8 опустился со второго на четвёртое место. OR по отдельным `Panel`, `Key`, `1`, `2` не гарантирует поиск именно сочетания двух нужных ключей. Короткие фрагменты с общими токенами могут получать высокий BM25.
- **Ветка Rick:** №15 опустился с четвёртого на пятое место, но из top-5 исчезли фрагменты альтернативной ветки Gail. Оба новых ответа указывают стартовую зону/Рика, тогда как старый Qwen смешал этапы, а старый GPT отказался отвечать. Возможная причина улучшения — состав остальных фрагментов; один прогон не доказывает механизм.
- **B2 Key Chip:** нужный №28 с кодом 0392 отсутствует в обеих выдачах. Оба GPT корректно уточняют комнату; оба Qwen ошибочно заявляют, что пароль не нужен. Частые слова `Key Chip` и номера предметов недостаточны для различения эпизодов.
- **Газ:** контекст одинаков в обоих режимах, правильный №19 первый. Оба Qwen искажают комбинацию; оба GPT сохраняют BLUE → GREEN → GREEN → RED → BLUE. Здесь FTS ничего не меняет; причина в генерации/понимании исходного текста с GRENN.
- **Emergency Box:** старый Qwen ошибочно разрешает хранить патроны, новый ограничивается лечебными предметами. Ответ улучшился при изменённом контексте, но одного сэмпла недостаточно для устойчивого вывода.
- **Начало:** одинаковый якорь №4–5 в обеих версиях. Оба Qwen добавляют несуществующее реанимационное оборудование; это не регрессия или улучшение FTS.

Правильные основные факты: Qwen 16/20 → 18/20, GPT 18/20 → 19/20. По строгому критерию целого ответа Qwen улучшился только с 10/20 до 11/20, GPT с 18/20 до 19/20. Сильная модель заметно надёжнее при шумном контексте; локальная продолжает добавлять неподтверждённые детали и лишние события.

Это 20 специально подобранных вопросов одной игры и один ответ на ячейку. У семи вопросов vector и hybrid передали полностью одинаковые контексты; различия их ответов являются вариативностью генерации. Показанные изменения нельзя переносить на все игры или считать статистически значимыми.

Следующие улучшения стоит проверять отдельным экспериментом: учитывать целые названия предметов/комнат, выбирать ветку и этап, добавить переранжирование и калибровать отбор контекста. Для кодов и комбинаций нужна отдельная проверка точности ответа. Набор этого прогона теперь является регрессионным, а для дальнейшей проверки обобщения нужен новый набор вопросов.

В исходниках `hybrid` включён по умолчанию; прежний режим доступен через `WALKTHROUGH_RETRIEVAL_MODE=vector`. Обновлённый daemon собран напрямую, `bin/.env` не перезаписывался. Он не запускался и не менял каталог базы. Временный llama.cpp запускался только для эксперимента и после прогона остановлен.

## Проверки воспроизводимости

- Старая реализация исполнена из сохранённых исходников через Go overlay на том же корпусе/embeddings; все 40 vector-ячеек совпадают с ней по контексту и system/user prompt. Только в отдельной проверке паритета генерация заменена заглушкой; 80 ответов основной матрицы — реальные.
- Во всех 40 парах HTTP/OpenCode совпадают контекст и точные system/user prompts.
- Независимый пересчёт SQLite BM25 + RRF/cosine подтвердил 36 выдач обычных запросов. Старт и ложная предпосылка используют прежний якорь.
- Между vector и hybrid полностью одинаковый контекст у 7 из 20 вопросов: beginning, first-generator, gas, false-premise, shotgun-location, mix-menu, turn-around. Разницу ответов в этих случаях нельзя приписывать FTS.
- Исходный корпус и набор вопросов не изменились; обе реализации и SHA исходников сохранены в `source/` и `source-hashes.json`.
- `go test -race -count=1 ./...`, `go vet ./...`, `git diff --check`: успешно. Добавлены тесты FTS-кандидата вне vector top-20, отсутствия лексических совпадений, безопасной токенизации, дедупликации и подключения текста вопроса к retrieval.

Время ячеек включает кеш embeddings, поиск, HTTP inference либо запуск OpenCode/сеть. Переключений embedding/generation модели между ячейками нет. Это не production latency и не чистая скорость inference.
